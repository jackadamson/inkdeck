## 1. Correctness bugs (fix regardless of any refactor)

Ordered roughly by severity. "confirmed" = reproduced with a scratch test;
"inspection" = evident from the code path, not executed.

- [ ] **P0 — Keyed reorders corrupt the host tree** (confirmed).
  `packages/inkdeck/src/renderer/hostConfig.ts:91-107`. `appendChild`,
  `insertBefore`, `appendChildToContainer`, `insertInContainerBefore` push /
  splice without first removing an existing occurrence of `child`. React
  *moves* keyed children by re-inserting them without a `removeChild`, so:
  `['A','B','C'] → ['C','A','B']` inside a key yields manifest text
  `["A","B","C","A","B"]` (duplicated glyphs); reordering keyed `<Key>`s under
  `<Deck>` puts the same HostElement in `children` twice and `#walkCommit`
  throws "two `<Key>` elements are mounted with position=…" on a valid app
  (`render`/`check`/`start` exit 1). Fix: splice out any existing index of
  `child` before inserting (what Ink / react-three-fiber do). Add a hostConfig
  unit test for keyed reorder at both levels.

- [ ] **P0 — exec mocking is a process global that leaks across sessions**
  (confirmed). `renderer/exec.ts:12`, `harness/session.ts:61,145`. With two
  live `renderDeck`/`HarnessSession`s, session B's mock table answers session
  A's `exec()` (observed: mic-mute session A flipped to MUTED by reading "0"
  from B's mocks). Whichever session shuts down first calls
  `setExecInterceptor(null)`, after which the survivor's `exec()` falls
  through to a **real `Bun.spawn`** — on macOS a test would really run
  `osascript … set volume input volume 0`. `unmatchedExecs` stays empty, so the
  gap is invisible. The interceptor also leaks if `HarnessSession.start()`
  throws after installing it. Fix: scope interception per session (see §3.4).

- [ ] **P0 — `dev` hot reload serves stale code for every file except the
  entry** (confirmed). `cli/start.ts:96`. `import(\`${app}?inkdeck-reload=N\`)`
  re-evaluates only `app.tsx`; modules it imports stay in the registry
  (probe: edit `dep.ts` + `entry.ts`, re-import entry with a new query →
  "entry(edited) sees v1"). Any app split across files silently runs old
  code after a save. Fix options in §4.1.

- [ ] **P1 — `#commitError` is never cleared** (confirmed).
  `renderer/controller.ts:102,260,343`. One bad save under `dev` (e.g. a
  duplicate position) makes every subsequent `settled()` rethrow the stale
  error although the fixed app committed and repainted → "reload failed: …"
  on every later save, never the repainted-keys line. Fix: reset at the start
  of `render()` / on the next successful commit, or consume-once when thrown.

- [ ] **P1 — `rendered` never fires (and `settled()` never resolves) under
  continuous animation** (confirmed). `renderer/controller.ts:486-521`.
  Listeners fire only in the `finally` when `#pendingRaster` fully drains; a
  poller committing faster than the flush loop rasterizes keeps the loop
  alive forever: the VirtualHandle receives frames continuously but
  `onRendered` fired 0 times in 3 s, `changed[]` grew to 1000+ entries, the
  simulator froze on frame 1, the agent never emitted `rendered`, and `dev`
  wedged at `await controller.settled()`. Fix: emit per flush *round* (dedupe
  `changed`), not only on full drain.

- [ ] **P1 — Frame marked as pushed before it is pushed** (inspection).
  `renderer/controller.ts:548-555`. `entry.rgba/rgbaHash` are assigned before
  `writeOutput`; if the write fails, scene-skip + output-dedup guarantee that
  frame is never re-sent — the key shows stale pixels until its content
  genuinely changes. Assign after the last packet succeeds (or clear in the
  catch). Related: the `DISCONNECT_GRACE_MS` sleep in the same catch stalls
  *all* keys for 1.2 s on any output error.

- [ ] **P1 — Contact-bounce filter breaks long-press and `useKeyState`**
  (confirmed). `renderer/controller.ts:566-589`. For a physical
  down→up→down bounce while the user keeps holding: the bounce "up" is
  processed as a real release (clears the long-press timer, fires `onPress`
  via the short-press path), then the bounce "down" is dropped by the
  debounce, so no timer is re-armed. Result with `FrozenClock`: after a 2 s
  hold, events == `['press']`, `onLongPress` never fires, `isPressed()` is
  false for the entire hold, and the real release is a no-op. Fix: make the
  filter symmetric — defer a release by the bounce window and cancel it if a
  re-press arrives (or treat an up→down pair inside the window as "still
  held"). Best done as part of extracting an input state machine (§3.1).

- [ ] **P1 — Back-to-back `tap()`s are silently dropped** (confirmed).
  `harness/session.ts:106-118`. Under real time (the `renderDeck`/agent
  default) `tap()` returns right after release, so the next `tap()`'s press
  lands inside the controller's 30 ms debounce: three taps → counter 2. Under
  frozen time `press(); release(); press()` has the same problem (clock never
  moves). In the agent the dropped press is acked with a plain `state`, so it
  looks like an ignored input, not an error. Fix: `tap()` sleeps/advances past
  the window after release in both clock modes; frozen `press()` directly
  after a `release()` should advance or throw with a pointer to
  `advanceTime`.

- [ ] **P1 — Raster failures are invisible to the manifest / `check`**
  (confirmed). `renderer/controller.ts:495-514`, `cli/check.ts:94`,
  `cli/render.ts:17`. `<img src="missing.png">` throws inside `renderScene`,
  is caught and only logged; the KeyEntry keeps `error: null, rgba: null`, so
  `check` prints OK / exit 0, `render` writes a manifest referencing a
  `key-N.png` it never wrote, and hardware keeps stale pixels. Fix: record
  the failure on the entry (`error` message) and paint the error tile, so the
  agent loop sees it structurally.

- [ ] **P1 — Removal detection misses fast re-enumeration** (inspection).
  `transport/iokit.ts:239-245`. Liveness is "is this *serial* still in the
  manager's set"; an unplug/replug or hub blip that completes between two 1 s
  polls yields a *new* `IOHIDDeviceRef` with the same serial, so the old
  (dead) handle is never `markRemoved()` (and the device-level removal
  callback is documented as never firing). Every write on the stale ref then
  fails → per-key error flood, no reconnect. Fix: compare the current
  `IOHIDDeviceRef` for that serial against the handle's ref.

- [ ] **P1 — A failed replug handshake kills the session** (inspection).
  `cli/start.ts:168-181`. Any throw from `replaceHandle()` (reset/brightness
  failing because the deck dropped again mid-handshake) → `shutdown(1)`,
  contradicting the DECISIONS entry that `start`/`dev` are session-keeping
  for launchd. Fix: loop back into `acquireDevice` for device-class
  failures; only exit on non-device errors.

- [ ] **P2 — `usePoller` captures the first callback forever** (inspection;
  the aurora example documents the workaround with `tickRef`).
  `renderer/hooks.ts:39-58`. Pollers that read props/state see mount-time
  values (`if (paused) return` never pauses). Fix: keep `fn` in a ref updated
  every render; `run` calls `ref.current`. Also see §4.2 (`refresh()`).

- [ ] **P2 — `serializeSvg` mangles camelCase SVG attributes** (inspection).
  `renderer/controller.ts:673-708`. Everything not in the 16-entry
  `SVG_CAMEL_ATTRS` allowlist is kebab-cased, so `stdDeviation`,
  `spreadMethod`, `pathLength`, `startOffset`, `baseFrequency`, `numOctaves`,
  `filterUnits`, `primitiveUnits`, `patternContentUnits`, `kernelMatrix`,
  `attributeName`, … become invalid names the rasterizer silently ignores
  (no blur, no spread, wrong pixels, no error). Fix: invert the rule —
  hyphenate only the known kebab-case presentation attributes
  (`strokeWidth`, `fillOpacity`, `stopColor`, `fontSize`, …) and pass
  everything else through verbatim; or adopt react-dom's table.

- [ ] **P2 — `onPress`/`onLongPress` types reject value-returning handlers**
  (confirmed by `tsc`). `renderer/components.ts:21-22`.
  `() => void | Promise<void>` rejects `() => count++` and any
  `() => somethingReturningAValue()`; the repo's own tests trip on it
  (`renderer.test.tsx:291`, `simulate.test.ts:22`). Use `() => unknown`.

- [ ] **P2 — `cli.test.ts` "list" fails off-macOS** (confirmed).
  `cli/cli.test.ts:81-91`. On Linux `list` prints the "hardware transport is
  not available" reason + `No devices.`; the test only accepts
  "no stream deck" or tab-separated device lines.

- [ ] **P3 — Simulator ignores initial brightness; re-encodes per socket**
  (inspection). `cli/simulate.ts:224-248` never applies `hello.brightness`,
  so `<Deck brightness={20}>` shows at 100 % until brightness changes again.
  `cli/simulate.ts:126-132` re-runs `keySnapshots()` (sorts all keys) and
  re-encodes the same PNG once per connected socket per changed key — encode
  once per key per batch and broadcast the same payload.

- [ ] **P3 — `parseArgs` strict-mode errors print a stack trace.**
  `cli/index.ts`. An unknown flag throws a `TypeError` that reaches `main`'s
  catch and is printed with a stack; catch it per command and print usage.

## 2. Packaging & dependencies

- [ ] **`react` → `peerDependencies`** (keep it in devDependencies for the
  repo's tests). A renderer that ships its own `react` will eventually give
  apps two React copies ("Invalid hook call"); workspace hoisting hides this
  today. Pin `react-reconciler` exactly and state the matching React range:
  0.32 ↔ React 19.1 officially, yet the lockfile already resolved React
  19.2.8 (which pairs with reconciler 0.33) — it works by luck of internals.
- [ ] **Remove `@takumi-rs/helpers`** — declared in
  `packages/inkdeck/package.json`, imported nowhere.
- [ ] **Evaluate removing `sharp` entirely** (probed; needs one hardware
  check). Takumi 2.5.4 alone covers everything sharp does here:
  - `render(…, { format: 'jpeg', quality: 95 })` produces baseline JPEG with
    **4:4:4** chroma (verified via `sharp(...).metadata()`), `format: 'png'`
    works, and raw RGBA can be fed back in as an `RgbaImage` node
    (`{ type: 'image', src: { width, height, data } }`) — identity re-encode
    is lossless (0 differing bytes).
  - The gen-2 flip is pixel-exact as CSS on that node:
    `transform: 'scale(-1,-1)'` (also `rotate(180deg)`) → **0 differing bytes**

    raster 1.30 ms/key), and it removes ~17 MB of libvips per platform plus a
    second native supply-chain surface — squarely in the spirit of SPEC §2.
  - Keep the canonical RGBA render for hashing/dedup; encode JPEG (device,
    flipped) and PNG (render/simulator, upright) from it via Takumi.
  - Gate: run `scripts/hardware-smoke.ts` with Takumi-encoded JPEGs on the XL
    before deleting sharp (different encoder; the deck has only ever been fed
    libjpeg-turbo/mozjpeg output). Then update SPEC §2/§6 and the goldens

- [ ] Add `"files"` to `packages/inkdeck/package.json` (exclude `*.test.*`,

- [ ] Relax `engines.bun` from the exact `"1.3.11"` to a range for the

- [ ] Move `InkdeckConfig` out of `src/index.ts` into its own module —

- [ ] Type model ids as `ModelId`, not `string`: `DeckInfo.model`

## 3. Architecture

### 3.1 Split `DeckController` (726 lines, ~9 responsibilities)

`renderer/controller.ts` owns the React root, commit walking + scene building,
SVG serialization, raster scheduling/coalescing/priority/dedup, input parsing
+ debounce + long-press, brightness, device attach/detach/replace, metrics and
handler-error routing. Proposed seams (each unit-testable without React or a
transport):

- [ ] `SceneBuilder`: host tree → `Map<position, KeyScene>` + validation
  (duplicate / negative / out-of-range positions). Pure function. Move
  `serializeSvg` next to `raster/scene.ts` — it is raster input, not control
  flow — and move `errorTileScene()` off `RasterEngine` into `scene.ts` as
  data.
- [ ] `InputMachine` (a.k.a. gesture recognizer): debounce + press /
  long-press state machine driven by the `Clock`. Pure; fixes bug §1 "bounce
  breaks long-press" properly and is where `onDoubleTap` ([P1]) lands.
- [ ] `FlushQueue`: coalescing, input-priority ordering, output dedup,
  per-round `rendered` emission, hash-after-push. Optionally rasterize keys in
  parallel (Takumi renders are async/native) and serialize only the HID
  writes — see §5.
- [ ] `DeviceLink`: handle attach/detach/replace, reset + brightness resend,
  disconnect classification. Replace
  `error.message.includes('IOHIDDeviceSetReport')` (`controller.ts:506`) with
  a typed `TransportIOError` thrown by transports, and move the "give removal
  detection one poll cycle" grace into `IOKitHandle` where that knowledge
  belongs.
- [ ] A tiny typed event emitter instead of six hand-rolled listener
  Sets/arrays, and an injected `Logger` (default: `[inkdeck] …` to stderr;
  agent: emits `log` events; tests: capture) instead of monkey-patching
  `console.error` process-wide (`cli/agent.ts:36-41`, and in
  `renderer.test.tsx` / `reconnect.test.tsx`).
- [ ] Inject `RasterEngine` (constructed by the boot function with fonts
  already loaded) instead of building it inside the controller; today CLI
  code reaches through `controller.raster.loadAppFonts/rgbaToPng`. Give the
  controller/session `keyPng(position)` for the simulator/render paths.

### 3.2 One way to boot a deck

There are three: `cli/headless.ts startHeadless` (render/check),
`HarnessSession.start` (agent/simulate/testing) and hand assembly in
`cli/start.ts` (hardware). Font loading, config handling and
start→render→settle are repeated in each; `cli/render.ts` re-implements
`HarnessSession.writeFrames` line for line; `start.ts waitForDevice`
re-implements `device/discovery.ts selectDevice`, which is now dead code.

- [ ] Single `bootDeck({ app, target: { handle, model, serial } | { virtual:
  model }, clock, exec, logger, debug })` → `DeckSession`. `HarnessSession`
  becomes a thin veneer (press/tap/advanceTime); delete `cli/headless.ts`;
  `render` = `session.writeFrames(outDir)`.
- [ ] `VirtualHandle.create(model)` (or `openVirtualDeck(model)`) to replace
  the `new VirtualTransport(m); await t.open('virtual:0'); t.handle` dance
  (6+ call sites; three private `mount()` helpers in tests).
- [ ] Have `waitForDevice` call `selectDevice` (treat "none attached" as
  keep-waiting) and delete the duplicate precedence/messaging.

### 3.3 CLI owns the process lifecycle

- [ ] Commands return `{ done: Promise<number>; shutdown(): Promise<void> }`;
  `cli/index.ts` alone installs SIGINT/SIGTERM and calls `process.exit`.
  Today `start.ts`, `simulate.ts` and `agent.ts` each install signal handlers,
  call `process.exit` from deep inside, and park on `new Promise(() => {})` —
  which is why `simulateCommand`/`startCommand` cannot be tested in-process
  and why `simulateCommand`'s shutdown has no double-invocation guard.

### 3.4 Session-scoped exec interception

- [ ] Run handler/poller invocations inside an `AsyncLocalStorage` scope owned
  by the session (context propagates through awaits and timers, so app code
  keeps calling plain `exec()`); resolve the interceptor from the store, fall
  back to a real spawn only when *no* session is active, and make "mocked
  session, no match" incapable of falling through. Fixes the P0 in §1 and
  lets test files run sessions concurrently.

### 3.5 Make `settled()` precise (ROADMAP already lists this as a gap)

- [ ] react-reconciler 0.32 exports `updateContainerSync`, `flushSyncWork`
  and `flushPassiveEffects` (verified in the installed build). Under frozen
  time + mocked exec everything is microtask-resolvable, so `settled()` can
  be an exact loop — flush passive effects → flush sync work → await the
  raster queue's *drained promise* → repeat until a full pass does no work —
  with zero sleeps. Keep the timed-quiescence heuristic only as the fallback
  for real-time mode with real I/O. Removes the 10–15 ms floor per call and
  makes agent acks event-precise.

### 3.6 Smaller structural items

- [ ] `KeyBoundary` never resets: a key that threw once stays on the error
  tile until a full remount. Reset when children change (the
  `react-error-boundary` `resetKeys` pattern) so a transient error recovers on
  the next good render.
- [ ] `takumi.ts:157` uses `require('node:fs').readFileSync` inside the render
  path of an ESM module — synchronous disk I/O on the input-pump thread. See
  §4.4 for the Takumi-idiomatic replacement.
- [ ] Type Takumi nodes with the exported `Node` type from `@takumi-rs/core`
  instead of `{ type; [key: string]: unknown }` + `render(node as never)`
  (`takumi.ts:12,39`); likewise replace `ReactReconciler(hostConfig as never)`
  (`hostConfig.ts:194`) with a local interface matching the 0.32 runtime so
  drift shows up as a type error in one place.
- [ ] `HostElement.props: Record<string, unknown>` → discriminated union per
  host type (`deck` / `key` / `keyerror` / content) so `controller.ts:415-423`
  stops casting; `SceneElement.tag: string` → `'div'|'span'|'p'|'img'|'svg'`.
- [ ] `harness/session.ts` stores `frozen: boolean` and casts
  `(this.clock as FrozenClock)` three times — hold `FrozenClock | null`.
- [ ] `sceneHash` comment claims key order is deterministic "by construction";
  true for framework keys, not for user `style` objects (`{a,b}` vs `{b,a}`
  hash differently → one redundant raster, caught by dedup). Either sort keys
  when hashing or fix the comment.
- [ ] `get deckInfo()` builds a new object per call (`controller.ts:179`) —
  cache it (see §4.2).
- [ ] `metrics.flushes` and `metrics.renders` are always incremented together
  — one field.
- [ ] Stale comments: `device/models.ts:12` and `device/protocol.ts:15` still
  say "NOT yet verified on real hardware"; `cli/start.ts:2-4,79-80` and
  `cli/headless.ts:1` describe M2/M3/M4 as future work.

## 4. Public API & DX (breaking changes welcome now)

### 4.1 Hot reload that actually reloads
- [ ] Either (a) run `dev` under `bun --hot` and park the transport handle +
  controller on `globalThis` / `import.meta.hot.data` so they survive module
  re-evaluation (Bun re-evaluates the changed module *and its importers*), or
  (b) keep cache-busting but watch the app directory recursively and document
  loudly that only the entry file reloads. Recommend (a); record it under
  SPEC §18.2 in DECISIONS. Also invalidate `RasterEngine`'s image cache on
  reload (it is keyed by unresolved `src` and never evicted).

### 4.2 Hooks
- [ ] `usePoller(fn, ms)`: latest-ref semantics (bug in §1) **and** return a
  `refresh()` so apps can re-poll immediately after acting
  (mic-mute: `toggle → exec → refresh()` instead of waiting ≤ 1 s for
  reconciliation).
- [ ] `useDeckInfo()`: return a stable object (effects keyed on it currently
  re-run every render); add `coordsOf(position)` / `positionOf(row, col)`
  helpers — every grid app writes `position % columns` by hand (see aurora).
- [ ] `useBrightness()`: stable setter identity (`useCallback` or a bound
  method).

### 4.3 Components
- [ ] `KeyProps.onPress/onLongPress: () => unknown` (§1).
- [ ] Adding `onLongPress` silently moves `onPress` from key-down to key-up.
  It is in DECISIONS but will surprise users: put it in the `KeyProps` JSDoc
  and README, or make it explicit (`pressOn?: 'down' | 'up'`).
- [ ] Accept `row`/`col` as an alternative to `position` on `<Key>`.
- [ ] Multiple children directly under `<Key>` get an implicit wrapper `div`
  (a Takumi flex *row*) — document it or require a single root element.
- [ ] `<Deck brightness>` removed after being set leaves the last value in
  place (no reset to default) — define and document.

### 4.4 Images & SVG
- [ ] `<img src>`: accept `Uint8Array` (Takumi supports it natively; SPEC §6.1
  promised "file path or Buffer"); reject `http(s):`/`data:` sources with a
  targeted message (today they are read from disk relative to the app dir and
  fail confusingly; no network by §16).
- [ ] Load image bytes asynchronously before render and hand them to Takumi
  through the `images: [{ src, data }]` render option (nodes reference the
  `src` string) so Takumi's decoded-image cache works across frames instead
  of re-passing raw bytes on every render.
- [ ] Pass `tagName` (and consider `@takumi-rs/helpers/jsx`'s
  `defaultStylePresets`) when converting scene → Takumi nodes so `p`/`span`
  semantics and stylesheet selectors behave as authors expect.
- [ ] Fix SVG attribute casing (§1).

### 4.5 Config, naming, protocol
- [ ] Rename `config.model` → `config.defaultModel` (it never constrains
  hardware; the name implies it does).
- [ ] Consider renaming `exec` while it is free: it takes an argv array
  (`spawn`/`execFile` semantics), not a shell string like
  `child_process.exec`. `run()` or `spawn()`.
- [ ] Agent protocol: echo an optional client-supplied `id` on the ack
  event(s). Under real time, unsolicited `rendered` events from pollers
  interleave with acks and clients cannot pair them; an `id` passthrough
  fixes that without changing the happy path.
- [ ] `KeyManifest.image` is always `key-N.png`, including in agent
  `rendered` events and the testing helper where no file exists — make it
  present only when frames were written, or document it as a naming hint.

### 4.6 Simulator hardening freebies
- [ ] `Content-Security-Policy` on the page response (`default-src 'none';
  img-src data:; connect-src ws://127.0.0.1:<port>; script-src 'unsafe-inline';
  style-src 'unsafe-inline'; frame-ancestors 'none'`), `timingSafeEqual` for
  the token compare, and apply `hello.brightness` (§1).

## 5. Performance (only where measured)

Headless Linux x64, aurora example on `xl` (32 keys, SVG per key), per frame:
~126 ms wall = Takumi raster 1.30 ms/key + sharp JPEG 1.78 ms/key + ~0.7 ms/key
React/serialize/framing/settled. The app ticks every 120 ms, so the pipeline
is at ~100 % of budget even before USB writes (ROADMAP's on-device metric of
~6 ms/key implies coalescing is already dropping frames on hardware — graceful,
but the effective frame rate is below the intended 8 fps).

- [ ] Takumi-only encode (§2): 126 → 94 ms/frame measured.
- [ ] Rasterize pending keys concurrently (`Promise.all` over Takumi renders,
  which run on native threads), keep HID writes sequential and
  input-prioritized. Expect a further large cut on multi-core machines.
- [ ] Emit `rendered` per round (§1) so the simulator/agent keep up under load.
- [ ] Simulator: one PNG encode per changed key per batch, broadcast to all
  sockets (§1).
